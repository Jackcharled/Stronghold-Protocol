# mm — 客户端注入脚本

本目录存放本分支的**界面定制代码**，以注入方式挂到游戏页面上，不改动游戏本体文件，因此跟随上游升级不会丢失。

## 文件

| 文件 | 说明 |
|---|---|
| `client.js` | 注入脚本，由反向代理在 `</body>` 前插入 `<script src="/mm/client.js"></script>` 加载（`Cache-Control: no-store`） |

## 包含的功能

1. 节点状态角标（延迟右侧，点击展开节点列表）
2. 临时公告（顶部滚动条，滚两遍后消失，同版本只推一次）
3. 更新公告（读取 `content/update.md`，每个版本弹一次）
4. 同盟密钥旁的 15 分钟倒计时（只在未开局时显示）
5. 同盟房间「匹配队友」入口（仅房主可点）
6. 按钮与布局修复（停止搜寻居中、延迟与按钮同行、节点面板定位等）
7. 界面精简（移除登录/注册入口与账号面板，游客直接进入游戏）

## 最近更新（2026-10-19）

1. **修复匹配成功后卡在「正在进入模拟…」**
   - 房主自动建房失败不再静默：重试次数 3 → 6，并在控制台输出 `[mm] 自动建房失败`;
   - 匹配成功界面停留 12 秒仍未进入时，自动出现「返回房间」按钮，避免无限等待。
2. **有 AI 队友时禁止匹配**
   - 房间内存在 AI 队友时，「匹配队友」按钮自动置灰，悬停提示「请先移除 AI 队友」；
   - 已在队列中的房间若添加了 AI，会自动退出排队并关闭匹配界面。
3. **修复注入脚本被反向代理静态规则拦截**
   - 反向代理需保证 `/mm/` 优先于静态资源规则（nginx 用 `location ^~ /mm/`）；
   - `/mm/client.js` 单独设置 `Cache-Control: no-store`，避免更新后玩家仍加载旧脚本。


## 部署方式

1. 把 `client.js` 放到任意可被站点访问的路径（例如服务器上的 `mm/client.js`）；
2. 在反向代理里对游戏首页做一次正文替换：

   ```nginx
   sub_filter '</body>' '<script src="/mm/client.js"></script></body>';
   sub_filter_once on;
   ```

3. 该脚本通过以下接口读取数据：

   | 接口 | 用途 |
   |---|---|
   | `GET /mm/api/announcement` | 临时公告内容 |
   | `GET /mm/api/update` | 更新公告（来自 `content/update.md`） |
   | `GET /mm/api/node-status` | 集群节点状态 |

## 说明

- 脚本对游戏状态只读，唯一的写操作是「建房时附带房间参数」，不涉及账号或存档；
- 若上游页面结构变化，脚本会自行降级（找不到元素时隐藏对应界面，不报错）；
- 与本分支的服务端改动配合使用，单独上传本脚本不会改变对局规则。
